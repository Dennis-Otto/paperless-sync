### Bug fixes

- **A document with a new file version in Paperless-ngx 3.x gets the content and the file type of that version:** Paperless serves the newest version of a document, while the fields of the document still describe its first file. A born-digital PDF added to a scan, which has no archived version, failed its document in every run with *Paperless did not return archive_checksum*, and its copy kept the old content for good; a version of another type, such as a text for a scanned PDF, got the extension of the first file. Now the copy takes the newest version, its archived version or else its original, with the extension of that file, in the same file in Nextcloud, which keeps its ID, its shares and its versions. A document that you merge into another one as a version counts as missing, and its copy goes as the deletion safety says. Paperless-ngx 2.x works as before.
