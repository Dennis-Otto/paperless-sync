### Bug fixes

- **A file replaced in the inbox after its upload goes to Paperless with its new content.** When the import of a file failed, such as a damaged scan, and someone saved a repaired version under the same name before the next run, the run moved the repaired file to the error folder, next to the reason of the old content, and it never reached Paperless. Now it stays in the inbox, the report names the failure of the former content, and the next run uploads the new one.
- **A tag that Paperless lacks is no longer lost without a word when files go by *Send to Paperless* or a rule of Flow.** With *Create missing tags* off, such a file went to Paperless without the tag, and nobody learned of it. Now the sender, also the owner of the files of a rule, gets one notification, *Sent to Paperless without the tags …*, which names the tags and the files, and the Nextcloud log has a warning, as for the inbox.
- **A copy that a stopped run wrote is no longer a conflict forever.** With *Skip and report conflict*, a run that stopped between writing a new copy, or moving one, and saving its path, such as at a restart of the server, left a copy that every later run reported as `Nextcloud file conflict at …`, so the document was never updated or moved again. Now a file at the path of the document with the content of the app's copy, or with the content of the document by the checksum of Paperless, counts as the app's own when the copy that the app knows of is gone.
