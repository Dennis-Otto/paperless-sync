### Bug fixes

- **The inbox no longer uploads a file a second time.** Before each upload, also the next attempt after a failed one, a run asks Paperless for a document with the content of the file, as *Send to Paperless* does, and ends the file as imported when Paperless has it, such as after an upload that Paperless received although its answer never came. A file that is renamed or moved inside the inbox, or whose folder is renamed, keeps its upload: a pending upload goes on at the new path, and a file kept after its import stays imported, so Paperless-ngx 3.x no longer gets a duplicate and 2.x no longer sends an imported file to the error folder. A file that Paperless refused still gets a new chance when it is renamed. In per-user ownership, a file with the same content as another user's document still goes up as a document of its own.
