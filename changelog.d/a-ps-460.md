### Bug fixes

- **A stored token that can no longer be decrypted no longer breaks Files.** After a restore or a move of Nextcloud with another `secret` in `config.php`, or with a damaged row of its credentials store, Files failed to load for every user, and the settings page that could take a new token failed too. Now such a token counts as none: Files, the settings page, the status API and the checks of *Administration → Overview* keep working, the settings say on top that the token has to be entered again, `occ paperless_sync:status` says so as well, also in its JSON output as `tokenUnreadable`, and the log has a warning. A webhook secret that can't be decrypted counts as none too, and a new one can be created. Files no longer reads and decrypts the token with every load, for every user: its menu and its note read the settings alone.
