### Bug fixes

- The **Nextcloud target user ID** is saved as Nextcloud spells the account name, such as `dennis` when you type `Dennis`, as the users of the tables of the ownership and of the tags are. Before, another case reached the right folder, but the activity entries and the notifications of failed imports went to an ID that no user has, and the check of the shares for **Tags that a user may see** found none. The update stores a target user saved in another case as Nextcloud spells it, once. A save now also refuses a new target user that Nextcloud doesn't have, and keeps a saved one that is gone since, so that a schedule can always be paused.
