### Bug fixes

- **A run of "Synchronize now" that the background jobs never start says so.** Before, the status said *Queued* for good, and the settings page kept asking for it, when the cron job of the system didn't run or Nextcloud lost the job. After 15 minutes, while no other run holds it back, the status says *Not started*, the bar of the buttons says so in the color of errors, with the last run of the background jobs of Nextcloud, so that you can check that they run, and the page stops asking. `occ paperless_sync:status` says the same.
- **A file sent to Paperless no longer stays pending for good when Paperless keeps refusing its new owner.** In per-user ownership, a refusal that repeats, such as 403 for an account that may no longer change the document or 400 for an owner that Paperless doesn't take, ends the import at once, and any other refusal a day after the upload: the document is in Paperless, so the sender hears that it is, with the reason why it keeps the owner that Paperless gave it, and may send the file again. A file of the inbox ends the same way, as imported, and the report of that run names the owner as an error once, instead of every run keeping the file in the inbox with the same error.
- **A sent file is no longer dropped as "deleted" when Nextcloud can't look it up for a moment.** When the lookup of a queued file fails while its user still exists, such as while a user backend like LDAP doesn't answer, the file waits for its next attempt, as after a failed upload, instead of ending with a notification that it was deleted, or, for a file of a rule of Flow, without reaching Paperless and without a word. A file that is gone, or whose sender's account was deleted, ends as before.
