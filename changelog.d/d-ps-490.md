### Bug fixes

- **New documents reach the archive again on Nextcloud 33.0.11, 34.0.6, 35.0.3 and newer.** Since an update to one of these versions, every run ended with *Completed with errors* and `No permission to move …/.<name>.paperless-<hex>.part` for each document that wasn't in the archive yet, while the copies that were there stayed up to date ([#490](https://github.com/Dennis-Otto/paperless-sync/issues/490)). A new copy is still written into a hidden temporary file first and appears at its place only once it is complete, now in a way that these versions of Nextcloud allow, and a write that fails removes its temporary file again. Each failed run had left such a hidden file, which Files doesn't show, in the data folder of the target user: the first run after the update removes them from the archive and the error folder, once, and touches no other file. The [troubleshooting page](https://dennis-otto.github.io/paperless-sync/troubleshooting.html#hidden-part-files-in-the-archive) says how to remove them by hand elsewhere.
